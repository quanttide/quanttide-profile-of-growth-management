# 留存（Retention）

## 核心逻辑：使用即沉淀，沉淀即成本

第二大脑的留存与其他产品相反：journal、profile、客户档案、学习档案每天在增长，数据迁出成本随使用时长单调上升。留存是 qtcloud 最不需要担心的环节——前提是用户真的把数据放了进来。

## 外部用户的渐进沉淀路径

外部用户不会第一天全量迁入，设计"逐步加深依赖"的阶梯：

1. **轻**：单篇笔记、第一份意图文档（价值感知期）
2. **中**：完整 profile 结构、写作云文库（习惯养成期）
3. **重**：全库结构 + 团队协作 + Agent 工作流绑定（生态锁定）

## 社区留存

GitHub Discussions 等社区互动是留存组件——通过学习产品建立关系（innovate.md），社区归属补足数据锁定之外的情感留存。

## 结构优先的维护原则（write.md 迁移）

帮用户维护结构而不是替用户做内容决策——AI 在没有规划信息时不做破坏性大范围操作。用户对结构的控制感是长期信任的基础。

## 度量

- 外部用户周活跃写入量
- 人均资产增长数（文档/契约/任务）
- 渐进路径的层级迁移率（轻→中→重）

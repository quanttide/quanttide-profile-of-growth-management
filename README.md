# 增长模型总纲

三业务 AARRR 的统一框架与当前行动重点。基于 2026-09-02 的两个关键判断：

## 两个核心判断

**1. 代金券 = 激活与留存的工具，不是收入。**

- 代金券的作用是让学员/执行方**跨过第一次真实参与**（激活），以及**持续参与**（留存）——它是参与循环的燃料，不是钱。
- **现金收入才进入 Revenue 环节**：一对一咨询（真实价格）、定制课、qtdata 项目款、未来的 qtcloud SaaS——只有外部现金流入才配叫收入。
- 按此修正：代金券从各业务的 Revenue 叙事中移除；qtclass 的 Revenue 只保留真实现金形态（咨询/课程）。

**2. 当前状态：券已发、未被用——先做激活。**

现状是发行侧跑起来了（四渠道发券），但核销侧为零：学员拿了券没有消费场景或没有意识到消费场景。**增长模型当前的全部重点在 Activation**——把"发出去的券"变成"被用掉的券"，激活闭环才算闭合。核销率（发券 → 核销）就是当前最重要的单一指标。

## 行动重点：把运营工作下放，管理层上移

把可标准化的运营工作**下放给学员/执行方作为练习兼考核**（他们完成任务挣券 → 我们完成运营），管理层把精力**上移**到方向、定价、体系设计：

| 下放的运营工作 | 承接者 | 双重收益 |
|---|---|---|
| 支持案例蒸馏（journal → profile 条目） | 实训学员 | 学员读懂业务（练习）+ 解决方案库增厚（运营） |
| 客户资料整理与历史盘点 | 实训学员/执行方 | qtdata 客户资产入库（激活/留存的地基） |
| 案例内容化（交付项目 → 公开案例页） | 商务方向学员 | qtdata 获客素材生产 |
| 学习中心/官网内容维护 | 产品方向学员 | 站点持续更新（如 learn 五文档的迭代） |
| 社区互动与反馈整理 | 执行方 | qtcrowd/qtcloud 社区经营起步 |

下放的设计原则：**每项下放工作本身就是一个标准任务**（有任务书、有验收准则、有代金券）——运营完成度与学员考核共用同一套体系，这正是"考核体系同时就是教育体系"在增长域的落地。

管理层上移的方向：增长模型本身的迭代（本档案）、定价体系设计、各业务北极星指标的校准、关键客户/关键学员的一对一。

## 三业务当前的激活重点

- **qtclass**：首任务 → 发券 → **引导核销**（券的购买力可见：完成页面引导至咨询预约）——核销率从 0 起步
- **qtdata**：新客户首封邮件 48h 需求文档草稿（激活定义不变）；老客户侧的发券（认错+感谢）同步设计核销引导
- **qtcloud**：代金券闭环本身就是支付系统的验证路径——核销数据直接喂给支付系统验证
